## Sources and design decisions

- PA2 frozen SRS and ID Registry; PA3 Software Design template.
- Q1 DBML: five PostgreSQL tables; role enum in `users`; `CopyStatus = Available/Borrowed/Reserved/Damaged/Lost`; `ReservationStatus = Pending/Ready/Fulfilled/Cancelled/Expired`; `Overdue` is computed from date fields.
- Q2 REST Contract: F02–F04 and F06 exact routes/payloads; base `/api`; nested `{error:{code,message}}` errors; pagination envelope; no client-provided `readerId` in `POST /reservations`.
- Architecture / deployment: React/Vite client, Express API, Prisma/PostgreSQL; server owns role checks, atomic Loans and Reservations, 60-second hold-expiry timer.

## Run and verify (after integration with a Vite project)

1. Copy `.env.example` to `src/client/.env.local` and keep `VITE_USE_MOCK=true`.
2. Import `api` in a frontend module: `import { api } from './api/endpoints.js';` (adjust path relative to the importing module).
3. Run `const result = await api.books.search({ q: 'Database', page: 1 }); console.log(result.items, result.pagination);`.
4. For role-restricted demo calls: `await api.auth.login({username:'reader.demo',password:'demo1234'});` then `await api.reservations.mine()`.
5. Check a mock error: `await api.reservations.create('00000000-0000-4000-8000-000000000100')` for the overdue Reader. Expect `ApiError` with `code='READER_OVERDUE'` and `status=422`.
6. Logout through `api.auth.logout()`; current-user mock endpoints will subsequently require login.
7. Real mode (`VITE_USE_MOCK=false`) requires `VITE_API_BASE_URL` and backend CORS to be configured.

The mock password and token are **demo-only** and MUST NOT be used for production authentication or regarded as secure JWT validation. Do not bundle server secrets into client assets.
