## 2. Chi tiết Triển khai Code (Code Implementation)

### 2.1 Backend Server (`src/server`)
* **Môi trường & Công nghệ:** Node.js 22 LTS, Express.js 4.21, Native ECMAScript Modules (`"type": "module"`).
* **Quản lý biến môi trường:** `config/env.js` đọc `.env`, fallback cấu hình mặc định an toàn (`PORT=4000`, `CORS_ORIGIN=http://localhost:5173`, `NODE_ENV=development`), đóng băng đối tượng cấu hình với `Object.freeze()`.
* **Middlewares cốt lõi:**
  * `requestId`: Tự động nhận diện hoặc sinh `UUIDv4`, gán vào `req.id` và header `x-request-id` để trace vết lỗi.
  * `errorHandler`: Middleware bắt lỗi tập trung, chuẩn hóa định dạng trả về JSON `{ error: { code, message, details } }`, ẩn stack trace ở tầng client, hỗ trợ lớp lỗi tùy biến `AppError`.
  * `notFound`: Bắt mọi route không hợp lệ, trả HTTP 404 với mã `NOT_FOUND`.
  * `helmet` & `cors`: Tăng cường bảo mật HTTP headers và giới hạn CORS origin.
* **Cơ chế Resilient Health Check (`GET /api/health`):**
  * Kiểm tra trạng thái cổng kết nối PostgreSQL 16 thông qua socket probe (`src/config/dbHealth.js`).
  * Trả về HTTP 200 `{ status: "ok", db: "up" | "down" }` ngay cả trên máy sạch chưa cài đặt hoặc chưa khởi động cơ sở dữ liệu PostgreSQL, đảm bảo zero crash.
* **Cấu trúc 7 Module nghiệp vụ (theo đúng phân rã SRS PA2 F01–F07):**
  * `src/modules/auth/`: Đăng nhập, đăng xuất, lấy thông tin cá nhân `me` (F01).
  * `src/modules/users/`: Quản trị tài khoản, danh sách, cập nhật trạng thái `ACTIVE`/`INACTIVE` (F01).
  * `src/modules/books/`: CRUD danh mục đầu sách, tìm kiếm đa tiêu chí, phân trang server-side (`NFR-01`), thống kê số lượng bản sao khả dụng (F02, F04).
  * `src/modules/copies/`: Quản lý bản sao vật lý, mã vạch barcode, vị trí kệ, quy tắc chặn xóa bản sao đang mượn (`BR-09`, F03).
  * `src/modules/loans/`: Quy trình mượn sách (kiểm tra hạn mức 3 cuốn `BR-01`, hạn 14 ngày `BR-02`, nợ quá hạn `BR-04`), trả sách (điều phối giữ chỗ `BR-08`), gia hạn (`BR-03`), danh sách quá hạn (F05).
  * `src/modules/reservations/`: Đặt trước sách khi hết bản sao (`BR-05`), hạn mức 2 cuốn (`BR-06`), hàng đợi FIFO (`BR-07`), thời hạn nhận sách 72 giờ (`BR-08`), hủy và nhận sách (F06).
  * `src/modules/dashboard/`: Bảng điều khiển bạn đọc (sách mượn, cảnh báo quá hạn) và bàn điều khiển thủ thư (F07).

### 2.2 Frontend Client Skeleton (`src/client`)
* Khởi tạo React 18 + Vite SPA, cấu hình proxy chuyển tiếp `/api` sang `http://localhost:4000`.
* Cấu hình Vitest + React Testing Library + jsdom với test suite mẫu kiểm tra trạng thái kết nối backend.
* Cấu hình ESLint độc lập cho frontend (`eslint.config.js`).

### 2.3 Nâng cấp CI Pipeline (`.github/workflows/ci.yml`)
* Chia tách thành 3 job rõ ràng:
  1. `repository-checks`: Kiểm tra merge conflict markers và tính toàn vẹn của README.
  2. `server-ci`: Cài đặt dependencies bằng `npm ci`, chạy `npm run lint` (ESLint) và `npm test` (Jest + Supertest trên Node 22).
  3. `client-ci`: Cài đặt dependencies bằng `npm ci`, chạy `npm run lint` (ESLint), `npm test` (Vitest) và `npm run build` (Vite production bundle).

## 5. Hướng dẫn Chạy và Kiểm thử (How to Run & Test)

### 5.1 Khởi chạy Backend độc lập
```bash
cd src/server
npm ci
npm run dev
```
Server chạy tại: `http://localhost:4000`

### 5.2 Kiểm tra Endpoint bằng curl
```bash
# 1. Health check (luôn trả 200 OK)
curl -i http://localhost:4000/api/health

# 2. Kiểm tra chuẩn mã lỗi 404
curl http://localhost:4000/api/non-existent

# 3. Kiểm tra endpoint module (ví dụ auth profile)
curl http://localhost:4000/api/v1/auth/me
```

### 5.3 Chạy toàn bộ Linter và Test Suites từ root
```bash
# Chạy cả test backend (Jest) và frontend (Vitest)
npm test

# Chạy cả linter backend và frontend
npm run lint
```
