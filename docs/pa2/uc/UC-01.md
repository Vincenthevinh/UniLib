## 1. Use Case Information

| Field | Description |
|---|---|
| Use Case ID | UC-01 |
| Use Case Name | Log In & Manage Session |
| Brief Description | Allows registered users to authenticate with username/email and password, establish a JWT-based session, access authorized functions according to their assigned roles, and log out. |
| Primary Actors | Reader, Librarian, Administrator |
| Secondary Actors | None |
| Priority | Must |
| Related Feature | F01 – User Authentication & Role-Based Access Control |
| Related Requirements | FR-F01-01, FR-F01-02, FR-F01-03 |

| Non-Functional Constraints | NFR-03, NFR-04, NFR-08 |
| Primary Screen | SCR-01 – Authentication & Login Screen |
| Trigger | A registered user opens the login screen and submits credentials. |

## 2. Preconditions

1. The UniLib web application and authentication service are available.
2. The user has a registered account with an assigned role.
3. The user is not currently authenticated when initiating the login flow.

## 3. Postconditions

### 3.1 Successful Login

1. The user's credentials are authenticated.
2. A valid JWT is generated and an authenticated client session is established.
3. The system applies the user's assigned role and access permissions.
4. The user is redirected to the approved role-specific landing page.

### 3.2 Successful Logout

1. The client-side session token is invalidated.
2. The authenticated client session is terminated.
3. The user is redirected to the login interface.

### 3.3 Failed Login

1. No authenticated session is created.
2. No JWT is issued.
3. The user remains on the login screen with an appropriate error message.

## 4. Main Success Flow – Login

1. The user opens the UniLib application.
2. The system displays the Login interface containing the Username or Email field, Password field, and Sign In button (SCR-01).
3. The user enters their registered username/email and password (SCR-01).
4. The user selects the Sign In button (SCR-01).
5. The system checks that the required credential fields are provided.
6. The system authenticates the submitted credentials against the registered account (FR-F01-01).
7. The system verifies that the account is permitted to authenticate.
8. The system generates a secure JWT following successful authentication (FR-F01-02).
9. The system establishes an authenticated session and applies role-based access control according to BR-10.
10. The system redirects the user to the team-approved landing page according to the assigned role:
    - Reader → Catalog (SCR-05).
    - Librarian → Book Catalog Management (SCR-03).
    - Administrator → User Management (SCR-02).
11. The user can access functions authorized for their assigned role.

## 5. Alternative Flows

### A1 – Invalid Username/Email or Password

**Entry point:** Main Flow, Step 6.

1. The system detects invalid or mismatched login credentials.
2. The system rejects the authentication request.
3. The system displays the error alert "Unable to sign in" with the message "Invalid username/email or password" on SCR-01.
4. The system does not generate a JWT or establish a session.
5. The user may correct the credentials and select Sign In again.
6. The flow resumes at Main Flow, Step 4.

**Postcondition:** The user remains unauthenticated until valid credentials are provided.

**Figma Reference:** Frame 1 – Login Error.

### A2 – Missing Required Credentials

**Entry point:** Main Flow, Step 5.

1. The system detects that the Username/Email or Password field is empty.
2. The system prevents the incomplete login request from succeeding.
3. The system indicates the missing required information on SCR-01.
4. The user may complete the missing field and resubmit the form.

**Postcondition:** No session is created while required credentials are missing.

**Note:** The exact missing-field validation presentation requires UI confirmation.

### A3 – User Logs Out

**Entry condition:** The user has an active authenticated session.

1. The user selects the Logout action from the authenticated interface.
2. The system invalidates the client-side session token (FR-F01-03).
3. The system terminates the authenticated client session.
4. The system redirects the user to the Login interface (SCR-01).

**Postcondition:** The user is logged out and cannot access protected functions through the terminated client session.

## 6. Exception Flows

### E1 – Deactivated Account

**Entry point:** Main Flow, Step 7.

1. The system identifies that the account has been deactivated by an Administrator.
2. The system rejects the login request.
3. The system does not generate a JWT.
4. The system displays an authentication error on SCR-01.
5. The user remains unauthenticated.

**Postcondition:** No authenticated session is established.

### E2 – Locked Account

**Entry point:** Main Flow, Step 7, if a separate locked status is supported.

1. The system identifies the account as locked.
2. The system rejects the login request.
3. The system does not create an authenticated session.
4. The system displays an appropriate authentication error on SCR-01.

**[TBD: Confirm whether Locked is a separate account state or is handled through Administrator deactivation. The frozen requirements do not define an automatic lockout threshold or duration.]**

### E3 – Authentication Service or Network Failure

**Entry point:** Main Flow, Step 6 or Step 8.

1. The authentication request cannot be completed because of network failure or backend service unavailability.
2. The system does not report a successful login or establish an authenticated session.
3. The system displays a user-friendly error notification on SCR-01, consistent with NFR-08.
4. The user may retry when the service becomes available.

**Postcondition:** The user remains unauthenticated.

## 7. Business Rules

| Rule ID | Business Rule |
|---|---|
| BR-10 | Role-based access permissions separate Reader, Librarian, and Administrator operations. Readers have read-only catalog access; Librarians perform authorized circulation operations; Administrators manage staff credentials. |

## 8. Non-Functional Constraints

| NFR ID | Constraint |
|---|---|
| NFR-03 | Passwords must be stored using bcrypt hashing with at least 10 salt rounds. Plain-text credentials must not be logged or returned in response payloads. |
| NFR-04 | Protected REST API endpoints must validate JWT claims. Unauthenticated requests return HTTP 401; unauthorized roles return HTTP 403. |
| NFR-08 | Network and backend failures must produce user-friendly error notifications without crashing the frontend. |
