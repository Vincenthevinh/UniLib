## 1. Use Case Information

| Field | Description |
|---|---|
| Use Case ID | UC-01 |
| Use Case Name | Log In & Manage Session |
| Description | Allows registered users to authenticate using their credentials, access the system according to their assigned roles, and terminate their sessions through logout. |
| Primary Actors | Reader, Librarian, Administrator |
| Priority | Must |
| Related Feature | F01 – User Authentication & Role-Based Access Control |
| Related Requirements | FR-F01-01, FR-F01-02, FR-F01-03 |
| Related Business Rules | BR-10 |
| Related NFRs | NFR-03, NFR-04 |
| Primary Screen | SCR-01 |
| Trigger | A user opens the login interface and submits credentials. |

## 2. Preconditions

1. The UniLib authentication service is available.
2. The user has a registered account with assigned role information.
3. The user is not currently authenticated for the login flow.

## 3. Postconditions

**Success:**

1. The system authenticates the user.
2. A valid JWT is issued and the authenticated session is established.
3. The user is directed to an appropriate role-specific interface.

**Failure:**

1. No authenticated session is created.
2. Protected system functions remain inaccessible to the unauthenticated user.

## 4. Main Success Flow

| Step | Actor | Action |
|---|---|---|
| 1 | User | Opens the authentication interface (SCR-01). |
| 2 | System | Displays the username/email and password fields (SCR-01). |
| 3 | User | Enters valid credentials and submits the login form (SCR-01). |
| 4 | System | Validates the submitted credentials against the registered account. |
| 5 | System | Confirms that the account is permitted to authenticate. |
| 6 | System | Generates a valid JWT and establishes an authenticated session (FR-F01-02). |
| 7 | System | Determines the user's assigned role according to BR-10. |
| 8 | System | Redirects the user to the appropriate authorized interface. |
| 9 | User | Accesses permitted functions according to the assigned role. |

## 5. Alternative Flows

### A1 – User Logs Out

**Entry condition:** The user has an active authenticated session.

1. The user selects the Logout action from the authenticated interface.
2. The system invalidates the client-side session token (FR-F01-03).
3. The system terminates the local authenticated session.
4. The system redirects the user to the login interface (SCR-01).

**Postcondition:** The user is logged out and cannot access protected functions using the terminated client-side session.

### A2 – Account Is Inactive

**Entry point:** Main Flow, Step 5.

1. The system identifies the account as inactive or deactivated.
2. The system refuses authentication.
3. The system displays an authentication failure message on SCR-01.
4. The user remains unauthenticated.

**Postcondition:** No JWT is issued.

## 6. Exception Flows

### E1 – Invalid Credentials

**Entry point:** Main Flow, Step 4.

1. The system detects an invalid username/email or password.
2. The system rejects the authentication attempt.
3. The system displays an error message on SCR-01 without disclosing sensitive account information.
4. The user may correct the credentials and retry.

**Postcondition:** No authenticated session is created.

### E2 – Authentication Service Unavailable

**Entry point:** Main Flow, Step 4.

1. The authentication service cannot complete the request.
2. The system displays an appropriate error message on SCR-01.
3. The system does not create an authenticated session.
4. The user may retry after service availability is restored.

## 7. Business Rules and NFR Constraints

- **BR-10:** Access privileges depend on assigned user roles.
- **NFR-03:** Stored passwords must be protected using the approved password-hashing requirements.
- **NFR-04:** Protected API endpoints must validate JWT claims and reject unauthorized access.
- **NFR-08:** Service failures must produce user-friendly error messages.

## 8. Related Acceptance Criteria

- AC-F01-01 – Successful authentication.
- AC-F01-02 – Invalid credentials.
- AC-F01-03 – Role-based access restrictions.
