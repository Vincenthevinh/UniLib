# UC-08 — Return Book (Circulation Check-in)

**Feature:** F05 (Must) with F06 hold routing | **Primary actor:** Librarian | **Screen:** SCR-08
**Linked requirements:** FR-F05-04, FR-F05-05, FR-F06-04, BR-07, BR-08, BR-09, NFR-05
**Task:** PA2-Q4 | **Owner:** Tran Ha Anh Quan | **Reviewer:** Nguyen / Vinh
**Status:** Ready for peer review | **Registry:** v1.0.0-frozen

## Goal and scope

The Librarian records the physical return of one borrowed copy, closes its Active Loan, and either releases the copy as Available or assigns it to the earliest eligible waiting Reservation for its Book Title, starting a 72-hour pickup window atomically.

## Trigger, preconditions and guarantees

- **Trigger:** A physical Book Copy is presented for return.
- **Preconditions:** Authenticated Librarian; Copy ID resolves to a Borrowed copy with exactly one active Loan.
- **Success postconditions:** Loan has a Return Timestamp and is Returned; the copy is either Available (no eligible waiting hold) or Reserved for one FIFO Reader with pickup deadline = allocation time + 72 hours. Aggregate counts reflect committed states.
- **Failure guarantee:** Failed or duplicated returns do not close a second Loan or allocate a hold twice.

## Main success scenario — No waiting reservation

1. Librarian opens SCR-08 and enters the Copy ID.
2. UniLib retrieves the active Loan, Reader, Book Title, current status and due date.
3. Librarian reviews the return summary and records optional condition notes.
4. Librarian confirms Return.
5. UniLib opens a transaction and locks the active Loan, copy and title reservation queue consistently.
6. UniLib revalidates that the Loan is Active and the copy Borrowed.
7. When there is no eligible waiting Reservation for the Book Title, UniLib records the return timestamp, marks the Loan Returned and the Copy Available.
8. UniLib commits and displays a return confirmation with the resulting copy status.

## Alternate and exception flows

- **A1 — Pending FIFO reservation:** At step 7, if eligible waiting holds exist, select the earliest by creation timestamp (stable tie-breaker by reservation ID). In the same transaction, mark the Loan Returned, designate that Reader as the hold owner, set copy Reserved, and set pickup deadline to allocation time + 72 hours. Display destination hold shelf information on SCR-08/SCR-10.
- **A2 — Condition note:** Store visible physical-condition notes from step 3 without silently converting a Borrowed copy to Available when the material is damaged. The decision for damaged returns is unresolved; stop or divert to a review-approved exception path.
- **E1 — Unknown Copy ID:** No write, show validation error.
- **E2 — Already Returned / copy not Borrowed:** Reject duplicate check-in with a current-state message; do not create a second return event.
- **E3 — Concurrent check-in or reservation change:** Lock and recompute queue in transaction; only one request can close the Loan / allocate the copy.
- **E4 — Database or allocation failure:** Roll back the loan closing and copy/hold changes together.
- **E5 — Unauthorized:** Non-Librarian actions are rejected by RBAC.

## State and ordering invariants

A single copy cannot be Borrowed and Reserved at the same time. A single hold cannot own two allocations, and one copy cannot be assigned to two Readers. Queue ordering is by creation time (BR-07); ties must be stable and testable. Eligibility must be rechecked as the queue advances; the frozen rules do not specify the disposition of an ineligible head-of-queue Reader, so this is a review decision. A Reserved copy never becomes Available while its allocated hold is active.
