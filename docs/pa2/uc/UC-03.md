## 1. Use Case Information

| Field | Description |
|---|---|
| Use Case ID | UC-03 |
| Use Case Name | Manage Book Catalog (CRUD Titles) |
| Brief Description | Allows authorized Librarians to create, view, update, and conditionally delete or deactivate Book Title records while maintaining ISBN uniqueness, catalog metadata, and aggregated physical Book Copy information. |
| Primary Actor | Librarian |
| Secondary Actors | None |
| Priority | Must |
| Related Feature | F02 – Book Catalog Management |
| Related Requirements | FR-F02-01, FR-F02-02, FR-F02-03, FR-F02-04 |
| Related Business Rules | BR-09, BR-10 |
| Non-Functional Constraints | NFR-04, NFR-05, NFR-06, NFR-08 |
| Primary Screen | SCR-03 – Librarian Book Catalog Management Screen |
| Related Screen | SCR-06 – Book Title Detail & Availability Screen |
| Trigger | An authorized Librarian opens Book Catalog Management to create, view, update, or delete/deactivate Book Title information. |

## 2. Preconditions

1. The UniLib application and catalog service are available.
2. The Librarian has an authenticated session.
3. The Librarian has the required catalog-management permissions.
4. For Update, View, or Delete/Deactivate operations, the target Book Title exists in the catalog.

## 3. Postconditions

### 3.1 Successful Creation

1. A new Book Title is stored with a unique ISBN.
2. The required metadata is recorded correctly.
3. The new Book Title becomes available in the catalog.

### 3.2 Successful Update

1. The selected Book Title metadata is updated.
2. Existing Book Copy associations remain consistent.
3. The updated information is available for subsequent catalog queries.

### 3.3 Successful Viewing

1. The requested Book Title details are displayed.
2. Aggregated Book Copy statistics are calculated from the associated physical copies.
3. No catalog record is modified.

### 3.4 Successful Deletion/Deactivation

1. An eligible Book Title is deleted or deactivated according to the approved catalog operation.
2. Referential integrity constraints are preserved.
3. The system displays the resulting catalog state.

### 3.5 Failure

1. Invalid or unauthorized operations are rejected.
2. Existing valid catalog records remain unchanged.
3. The system displays an appropriate error message.

## 4. Main Success Flow – Create Book Title

1. The Librarian accesses the Book Catalog Management interface (SCR-03).
2. The system displays the catalog-management view and existing Book Title records (SCR-03).
3. The Librarian selects the Add Book Title action (SCR-03).
4. The system displays the Book Title creation form (SCR-03).
5. The Librarian enters the required metadata: ISBN, Title, Author(s), Category, Publisher, and Publication Year.
6. The Librarian submits the completed form (SCR-03).
7. The system validates the required metadata fields.
8. The system checks whether the ISBN is unique (FR-F02-01).
9. The system creates the new Book Title record.
10. The system confirms successful creation and displays the updated catalog (SCR-03).
11. The Librarian may review the new Book Title details.

**Design Note:** The CRUD interactions above follow the frozen SCR-03 Registry description. The supplied Figma screenshots do not show the Librarian management interface, so the exact form and control presentation require verification.

## 5. Alternative Flows

### A1 – View Book Title Details and Availability

**Entry point:** Main Flow, Step 2.

1. The Librarian selects an existing Book Title from the catalog (SCR-03).
2. The system retrieves the selected Book Title information.
3. The system calculates the Total Copies, Available Copies, Borrowed Copies, and Reserved Copies associated with the Book Title (FR-F02-04).
4. The system displays the Book Title detail and availability information (SCR-06).
5. The Librarian reviews the metadata and Book Copy information.

**Postcondition:** No catalog data is modified.

**Figma References:** Frames 10, 11, and 12 – Catalog View Details.

### A2 – Edit Book Title Metadata

**Entry point:** Main Flow, Step 2.

1. The Librarian selects an existing Book Title (SCR-03).
2. The Librarian selects the Edit action (SCR-03).
3. The system displays the existing Book Title metadata.
4. The Librarian updates one or more permitted metadata fields.
5. The Librarian submits the changes (SCR-03).
6. The system validates the updated metadata.
7. The system checks ISBN uniqueness if the ISBN is editable and has changed.
8. The system saves the updated Book Title metadata (FR-F02-02).
9. The system displays the updated record (SCR-03).

**Postcondition:** The Book Title metadata is updated while its physical Book Copy associations remain valid.

### A3 – Delete or Deactivate an Eligible Book Title

**Entry point:** Main Flow, Step 2.

1. The Librarian selects an existing Book Title (SCR-03).
2. The Librarian initiates the Delete/Deactivate action (SCR-03).
3. The system checks for associated physical Book Copies, active Loans, and pending Reservations.
4. The system verifies that the operation satisfies FR-F02-03 and BR-09.
5. The system proceeds with the permitted deletion/deactivation operation.
6. The system updates the catalog and displays the operation result (SCR-03).

**Postcondition:** Only an eligible Book Title can be deleted/deactivated.

## 6. Exception Flows

### E1 – Duplicate ISBN

**Entry point:** Main Flow, Step 8.

1. The system identifies an existing Book Title with the submitted ISBN.
2. The system rejects the creation request.
3. The system displays a duplicate ISBN error on SCR-03.
4. The system does not create a duplicate Book Title.
5. The Librarian may correct the ISBN and resubmit the form.

**Postcondition:** ISBN uniqueness is preserved.

### E2 – Book Title Has Linked Physical Copies or Circulation Records

**Entry point:** Alternative Flow A3, Step 3.

1. The system detects one or more associated physical Book Copies, active Loans, or pending Reservations.
2. The system blocks the deletion/deactivation operation according to FR-F02-03 and BR-09.
3. The system displays an explanation on SCR-03.
4. The Book Title and associated records remain unchanged.

**Postcondition:** Referential integrity is preserved.

### E3 – Invalid or Missing Book Title Metadata

**Entry point:** Main Flow, Step 7, or Alternative Flow A2, Step 6.

1. The system detects invalid or incomplete required metadata.
2. The system rejects the submitted information.
3. The system indicates the affected fields on SCR-03.
4. The Librarian may correct the information and resubmit.

**Postcondition:** Invalid catalog metadata is not saved.

### E4 – Unauthorized Access

**Entry condition:** A user without Librarian permissions attempts a catalog-management operation.

1. The system validates the requester's JWT and role.
2. The system rejects the unauthorized operation according to NFR-04.
3. The system returns HTTP 401 for unauthenticated access or HTTP 403 for an authenticated but unauthorized role.
4. Existing catalog data remains unchanged.

**Postcondition:** No unauthorized catalog modification occurs.

### E5 – Database or Network Failure

1. The system cannot complete the requested catalog operation.
2. The system does not report a successful modification.
3. The system prevents partial persistence of an unsuccessful data-changing operation.
4. The system displays a user-friendly error notification on SCR-03.

**Postcondition:** No partially completed catalog modification is reported as successful.

## 7. Business Rules

| Rule ID | Business Rule |
|---|---|
| BR-09 | A Book Title cannot be deleted while physical copies exist in inventory. A physical Book Copy cannot be removed or decommissioned while Borrowed or Reserved. |
| BR-10 | Catalog management is restricted to authorized Librarians; Readers have read-only catalog access. |

FR-F02-03 additionally requires no associated physical copies, active Loans, or pending Reservations before title deletion/deactivation. This restriction must be preserved.

## 8. Non-Functional Constraints

| NFR ID | Constraint |
|---|---|
| NFR-04 | Protected REST endpoints must validate JWT claims and enforce authorization using HTTP 401/403 where applicable. |
| NFR-05 | Applicable concurrent data operations must preserve database integrity through atomic transactions and row-level locking. |
| NFR-06 | UI controls must satisfy the approved accessibility and keyboard-navigation requirements. |
| NFR-08 | Backend and network failures must be handled through user-friendly error messages without crashing the frontend. |
