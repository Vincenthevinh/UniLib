## 1. Use Case Information

| Field | Specification |
|---|---|
| Use Case ID | UC-11 |
| Use Case Name | Cancel Reservation & Process Expiry |
| Brief Description | Allows a Reader to cancel an active pending Reservation and allows the system to expire an uncollected allocated hold after its 72-hour Pickup Window, maintaining FIFO order and consistent Book Copy status. |
| Primary Actors | Reader; System (automatic expiry) |
| Supporting Actor | Librarian (hold-shelf oversight) |
| Priority | Must |
| Related Feature | F06 — Book Reservation |
| Related Requirements | FR-F06-04, FR-F06-05 |
| Related Business Rules | BR-07, BR-08 |
| Trigger | The Reader chooses Cancel on an active Reservation, or the 72-hour Pickup Deadline passes without collection of a held copy. |
| Primary Screen | SCR-11 — Reader Personal Dashboard Screen (Reader cancellation) |
| Related Screen | SCR-10 — Librarian Hold Shelf & Reservation Queue Screen (allocated holds and expiry) |
| Preconditions | 1. The Reader is authenticated to cancel their own Reservation, or the system is processing an expired hold. 2. The Reservation exists and is eligible for the requested cancellation/expiry. 3. For automatic expiry, a Book Copy has been allocated in Reserved status and its 72-hour Pickup Deadline has elapsed. |
| Success Postconditions | The Reservation is marked Canceled or Expired as appropriate; the title's FIFO queue is updated. If an allocated Book Copy is released, it is reassigned to the next eligible FIFO Reader and remains Reserved with a new Pickup Window, or transitions to Available when no eligible Reservation remains. |
| Failure Postconditions | Invalid or unauthorized requests do not modify the Reservation or Book Copy state; the system reports the failure. |

## 2. Main Success Flow — Reader Cancels a Pending Reservation

1. The Reader opens My Dashboard and chooses My Reservations (SCR-11).
2. The system displays the Reader's active Reservation list with Book Title, Reservation Date, Queue Position, Status, Pickup Deadline (if applicable), and Cancel action (SCR-11).
3. The Reader selects Cancel on a pending Reservation (SCR-11).
4. The system validates that the Reservation belongs to the authenticated Reader and is eligible for cancellation.
5. The system marks the Reservation as Canceled (FR-F06-05).
6. The system removes the canceled Reservation from the active FIFO queue and updates the remaining queue positions according to BR-07.
7. The system refreshes My Reservations and the active Reservation count on SCR-11.
8. The system displays a confirmation that the Reservation was canceled and the FIFO queue updated (SCR-11).
9. The use case ends successfully.

## 3. Alternative Flows

### A1 — Reader cancels an allocated hold (Reserved copy)

1. The Reader selects Cancel for an allocated Reservation on SCR-11.

   [TBD: Confirm whether cancellation is permitted after a copy reaches Reserved/Ready status and how this is shown on SCR-11.]

2. The system validates the Reader's ownership of the active Reservation.
3. The system cancels the Reservation and releases its allocated Book Copy.
4. If another eligible Reservation exists, the system assigns the copy to the next FIFO Reader, keeps the copy status Reserved, and starts a new 72-hour Pickup Window (BR-07, BR-08).
5. Otherwise, the system transitions the Book Copy from Reserved to Available.
6. The system refreshes the Reader view (SCR-11) and the hold queue (SCR-10).

### A2 — Automatic expiry of an uncollected allocated hold

1. The system identifies an allocated hold whose 72-hour Pickup Window has elapsed without collection (FR-F06-04, BR-08).
2. The system marks the corresponding Reservation as Expired (FR-F06-05).
3. The system removes the expired Reservation from the active queue.
4. If another eligible Reservation exists, the system assigns the Book Copy to the next Reader in FIFO order, maintains Reserved status, and sets that Reader's 72-hour Pickup Deadline.
5. Otherwise, the system transitions the Book Copy to Available.
6. The system updates the hold shelf/queue information on SCR-10 and the affected Reader reservation information on SCR-11 when accessed.
7. The automatic expiry flow ends.

## 4. Exception Flows

### E1 — Reservation already canceled, expired, or fulfilled (at step 4)

1. The system finds that the Reservation is no longer eligible for cancellation.
2. The system rejects the request without changing the current Reservation or Book Copy status.
3. The system displays the current status on SCR-11.

### E2 — Unauthorized cancellation (at step 4)

1. The system detects that the authenticated Reader does not own the selected Reservation, or that the caller is not authenticated.
2. The system rejects the request under NFR-04.
3. No queue position or Book Copy status changes.

### E3 — Concurrent cancellation, collection, or expiry

1. The system detects a conflicting operation affecting the same Reservation or Book Copy.
2. The system prevents duplicate release or reassignment through consistent, atomic state changes (NFR-05).
3. The system displays the actual current state on SCR-11 or SCR-10, as applicable.
4. The operation may be retried only if the Reservation remains eligible.

### E4 — Service or network failure

1. The cancellation or expiry operation cannot be completed.
2. The system does not report success without a confirmed state update.
3. The interface displays a user-friendly error according to NFR-08.

## 5. Business Rules

| ID | Rule application |
|---|---|
| BR-07 | Reservation allocation follows First-In, First-Out order based on creation timestamps; cancellation removes the canceled queue entry without changing the relative order of remaining entries. |
| BR-08 | A returned copy allocated to a Reader enters Reserved state for exactly 72 hours. An uncollected hold expires and the Book Copy is routed to the next FIFO Reader or becomes Available. |

**Important distinction:** A pending Reservation without an allocated Book Copy has no active Pickup Window. Cancellation of such a Reservation updates the queue but does not release a physical Book Copy.

## 6. Non-Functional Constraints

| ID | Constraint |
|---|---|
| NFR-04 | Protected Reservation endpoints validate JWT claims and reject unauthorized access. |
| NFR-05 | Queue changes, expiration, and Book Copy reallocation require atomic state transitions to prevent races or duplicate holds. |
| NFR-06 | Reader-facing cancellation controls must satisfy the approved accessibility requirements. |
| NFR-08 | Service/network failures must not crash the interface or display unverified success messages. |

## 8. Figma and State-Transition Notes

- Frame 6 — My Reservations: Pending Reservation, FIFO Queue Position, and a Pickup Deadline reading "Starts when a copy is assigned."
- Frame 7 — My Reservations after cancel: No active reservations; success banner says the FIFO queue has been updated.
- Frame 8 — Dashboard after cancel: Active Reservations count is 0/2 and a cancellation success banner appears.
- These frames support the pending-cancellation main flow. They do not visibly demonstrate cancellation of a Ready/Reserved hold or automatic 72-hour expiry; both require review with SCR-10 and Quân's state-transitions.md.
- Cross-check with UC-08: A returned Borrowed copy is assigned to the first eligible Reader's Reservation and becomes Reserved; cancellation or expiry of an allocated hold must release/reallocate the same physical copy consistently. Do not allocate a copy to two Readers.
