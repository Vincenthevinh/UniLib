# UC-07 — Borrow Book (Circulation Checkout)

**Feature:** F05 (Must), F06 fulfillment | **Primary actor:** Librarian | **Screen:** SCR-07
**Linked requirements:** FR-F05-01..FR-F05-03, FR-F06-06, BR-01, BR-02, BR-04, BR-10, NFR-05

**Status:** Ready for peer review | **Registry:** v1.0.0-frozen

## Goal and scope

A Librarian issues one physical Book Copy to an eligible Reader, records an active Loan with an exact 14-day Due Date and changes the copy to Borrowed atomically. This use case also supports pickup of a copy already held for the same Reader (FR-F06-06).

## Trigger, preconditions and guarantees

- **Trigger:** Reader presents a copy/hold at the circulation desk; Librarian starts Checkout.
- **Preconditions:** Librarian authenticated; Reader account exists and is Active; Book Copy and Reader IDs can be resolved.
- **Success postconditions:** Exactly one active Loan is created for the selected copy; Due Date is checkout timestamp + 14 calendar days; Book Copy becomes Borrowed. If fulfilled from a hold, that Reader's reservation is fulfilled in the same transaction.
- **Failure guarantee:** No partial Loan, Book Copy or Reservation changes.

## Main success scenario — Available copy

1. Librarian opens SCR-07 and enters/selects the Reader ID.
2. UniLib retrieves current account status, active Loan count and Overdue Loan count.
3. Librarian enters the physical Copy ID (manual barcode entry).
4. UniLib starts a database transaction and locks all mutable records needed for this checkout in a consistent order.
5. UniLib verifies Active account status, fewer than 3 active loans (BR-01), zero overdue loans (BR-04) and selected copy status Available.
6. UniLib creates exactly one Active Loan with checkout timestamp and Due Date 14 calendar days later.
7. UniLib sets the physical copy to Borrowed and commits the transaction.
8. UniLib displays a successful checkout receipt (Reader, Copy, checkout time and Due Date).

## Alternate and exception flows

- **A1 — Reserved pickup for the same Reader:** At step 5, if the copy is Reserved for this Reader and pickup has not expired, validate the assignment/deadline, mark the hold Fulfilled and execute steps 6–8 in one transaction (FR-F06-06). A Reserved copy belonging to a different Reader is never eligible.
- **E1 — Loan limit reached:** At step 5, >= 3 active loans; reject, explain BR-01 and roll back.
- **E2 — Overdue restriction:** At step 5, at least one overdue loan; reject under BR-04 and roll back.
- **E3 — Inactive or unknown Reader:** Reject with a safe account error.
- **E4 — Copy unavailable or stale view:** Borrowed, Damaged/Lost, or held for another Reader; reject with a state conflict and refresh availability.
- **E5 — Hold expired before pickup:** Reject pickup and route expiry through UC-11 before any new checkout.
- **E6 — Simultaneous checkout:** Competing requests for the final Available copy cannot both commit; one succeeds and the other sees a conflict.
- **E7 — Persistence/transaction failure:** Roll back all writes and display a retry-safe error without duplicate loans.
- **E8 — Unauthorized:** Missing/invalid token returns 401; Reader/Admin without circulation privilege returns 403.

## Consistency and implementation constraints

The eligibility check and state transition must run within the same database transaction, not as separate read-then-write calls. Locks and unique/exclusion constraints must prevent concurrent active loans for the same copy; use a consistent lock order with check-in and hold allocation. Revalidate everything when committing; UI availability badges are advisory.

The frozen AC expresses due date as "today + 14 days", whereas BR-02 speaks of 14 calendar days from checkout. Exact timestamp rounding/timezone behavior needs clarification, but the 14-day duration must not silently change.
