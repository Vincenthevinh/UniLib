## 1. Use Case Information

| Field | Specification |
|---|---|
| Use Case ID | UC-10 |
| Use Case Name | Reserve Book Title (Place Hold) |
| Brief Description | Allows an eligible Reader to request a Book Title when no associated physical Book Copy is Available, while enforcing borrowing restrictions, reservation limits, and a First-In, First-Out queue. |
| Primary Actor | Reader |
| Secondary Actor | UniLib system |
| Priority | Must |
| Related Feature | F06 — Book Reservation |
| Related Requirements | FR-F06-01, FR-F06-02, FR-F06-03 |
| Related Business Rules | BR-04, BR-05, BR-06, BR-07, BR-08 |
| Trigger | A Reader selects the reservation action for a Book Title with zero Available copies. |
| Primary Screen | SCR-09 — Book Reservation Modal / Confirmation View |
| Related Screens | SCR-06 — Book Title Detail & Availability; SCR-11 — Reader Personal Dashboard |
| Preconditions | 1. The Reader is authenticated and has an active account. 2. The selected Book Title exists. 3. There are zero Book Copies in Available status. 4. The Reader has no Overdue Loan, no active Loan for the same title, and fewer than two active Reservations. |
| Success Postconditions | One active pending Reservation for the selected Book Title is recorded at the end of its FIFO queue, with an assigned position based on creation order; no Book Copy is immediately checked out or marked Reserved solely by this request. |
| Failure Postconditions | No Reservation is created when an eligibility or availability rule fails; existing copy and queue states remain consistent. |

## 2. Main Success Flow — Place Reservation

1. The Reader navigates from the Catalog to a selected Book Title detail view (SCR-06).
2. The system shows title metadata and the current Book Copy availability counts on SCR-06.
3. The Reader selects Reserve Book when the title has zero Available Book Copies (SCR-06).

   [TBD: This action is defined in the frozen SCR-06 Registry but was not visible in the supplied available-copy detail screenshots.]

4. The system displays the Book Reservation confirmation view (SCR-09).
5. The Reader confirms the Reservation request on SCR-09.
6. The system verifies that the Reader has no Overdue Loans (BR-04), does not have an active Loan for this Book Title (BR-05), and has fewer than two active Reservations (BR-06).
7. The system rechecks that zero copies are currently Available (FR-F06-01, BR-05).
8. The system checks whether the Reader already has an active Reservation for the same Book Title.

   [TBD: Confirm that duplicate active Reservation rejection is an approved explicit rule; the N5 task requires it, but BR-05/BR-06 do not state it verbatim.]

9. The system creates a pending Reservation and appends it to the end of the title-specific FIFO queue according to the creation timestamp (FR-F06-03, BR-07).
10. The system displays the successful reservation confirmation and queue position (SCR-09).
11. The Reader may open the personal reservations list on SCR-11 to view the pending Reservation.
12. The use case ends successfully.

## 3. Alternative Flows

### A1 — Reader cancels before confirmation (at step 5)

1. The Reader dismisses the confirmation view (SCR-09).
2. The system returns to the Book Title detail view (SCR-06).
3. No Reservation is created.

### A2 — View a pending Reservation on the dashboard (after step 10)

1. The Reader opens My Dashboard → My Reservations (SCR-11).
2. The system displays the Book Title, Reservation Date, Queue Position, Status, and Pickup Deadline information if applicable.
3. The Reservation remains Pending until a copy is allocated by the hold-routing process.

## 4. Exception Flows

### E1 — At least one copy becomes Available (at step 7)

1. The system detects one or more Available copies.
2. The system rejects the Reservation request according to BR-05 and AC-F06-02.
3. The system directs the Reader to the availability information on SCR-06; checkout remains a Librarian circulation-desk action.

### E2 — Reservation eligibility failure (at step 6)

1. The system identifies an Overdue Loan, an active Loan for the same Book Title, or two existing active Reservations.
2. The system rejects the Reservation under BR-04, BR-05, or BR-06, as applicable.
3. The system displays an appropriate reason on SCR-09 and does not create a Reservation.

### E3 — Duplicate active Reservation (at step 8)

1. The system identifies an existing active Reservation for the same Reader and Book Title.
2. The system rejects a second Reservation and displays a message on SCR-09.
3. The existing Reservation and FIFO position remain unchanged.

[TBD: Confirm the explicit duplicate-Reservation business rule with PM/Quân before baseline.]

### E4 — Concurrent availability change or service failure (at steps 7–9)

1. The system detects that eligibility or copy availability changed during submission, or that the reservation service is unavailable.
2. The system does not persist a duplicate or partially created Reservation.
3. The system displays a user-friendly error on SCR-09 and allows the Reader to refresh the Book Title detail view.

## 5. Business Rules

| ID | Rule application |
|---|---|
| BR-04 | A Reader with an Overdue Loan cannot place a new Reservation. |
| BR-05 | A Reservation may be placed only when no copy is Available and the Reader has no active Loan for the same title. |
| BR-06 | A Reader may have at most two active Reservations. |
| BR-07 | The system appends new Reservations in strict creation-time FIFO order. |
| BR-08 | The 72-hour Pickup Window begins when a returned copy is routed to the Reader and becomes Reserved; it does not begin when the pending Reservation is created. |
