# ADR-001: Lựa chọn Hệ quản trị CSDL Quan hệ PostgreSQL 16 và Prisma ORM

* **Mã quyết định (Decision ID):** `ADR-001`
* **Ngày quyết định (Date):** 24/11/2026
* **Người đề xuất (Author):** Nguyễn Phan Thế Vinh (Team Lead / PM · Backend / Tester)
* **Người phản biện (Reviewer):** Trần Hà Anh Quân (Fullstack Developer / Tech Lead)
* **Trạng thái (Status):** Accepted (Đã phê duyệt và áp dụng chính thức)
* **Liên kết yêu cầu (Traceability):** FR-F01-01..04, FR-F02-01..04, FR-F03-01..04, FR-F05-01..07, FR-F06-01..06, BR-01..10, NFR-05

## 1. Bối cảnh và Đặt vấn đề (Context)

Hệ thống Quản lý Thư viện Đại học UniLib yêu cầu quản lý chặt chẽ 7 phân hệ chức năng (F01–F07) với độ phức tạp cao về quan hệ thực thể và tính toàn vẹn dữ liệu:
- Mối quan hệ giữa Người dùng (`User`), Đầu sách (`BookTitle`), Bản sao vật lý (`BookCopy`), Bản ghi Mượn trả (`Loan`), và Hàng đợi Đặt trước (`Reservation`).
- Các quy tắc nghiệp vụ lưu thông nghiêm ngặt: giới hạn mượn 3 cuốn (`BR-01`), hạn 14 ngày (`BR-02`), chỉ cho mượn/đặt trước khi không nợ quá hạn (`BR-04`), đặt trước FIFO (`BR-07`), thời hạn giữ chỗ 72 giờ (`BR-08`), toàn vẹn khóa ngoại chặn xóa đầu sách còn bản sao (`BR-09`).
- Yêu cầu phi chức năng cốt lõi `NFR-05` (Tính toàn vẹn và nhất quán dữ liệu): Ngăn chặn triệt để hiện tượng race condition khi nhiều bạn đọc cùng mượn hoặc cùng đặt trước một bản sao sách khả dụng tại cùng một thời điểm.
- Đội ngũ phát triển cần một công cụ quản lý lược đồ CSDL có khả năng di chuyển (migration), tự động đồng bộ kiểu dữ liệu (type-safe) sang mã nguồn Node.js, và hỗ trợ giao dịch ACID mạnh mẽ.

---

## 2. Quyết định Kiến trúc (Decision)

Nhóm T05 thống nhất quyết định:
1. **Lựa chọn PostgreSQL 16 làm Hệ quản trị CSDL quan hệ (RDBMS) duy nhất** cho toàn bộ hệ thống UniLib.
2. **Lựa chọn Prisma ORM (phiên bản 6.x) làm công cụ Object-Relational Mapping (ORM) và Data Access Layer (DAL)**.
3. **Quy chuẩn thiết kế dữ liệu:**
   - Quản lý lược đồ CSDL tập trung qua file `prisma/schema.prisma`.
   - Toàn bộ khóa chính sử dụng kiểu UUID v4 (`@default(uuid()) @db.Uuid`) để đảm bảo tính duy nhất toàn cầu và bảo mật chống dò quét ID.
   - Các mốc thời gian nghiệp vụ lưu dưới dạng `timestamptz(3)` để bảo toàn múi giờ UTC.
   - Toàn bộ khóa ngoại thiết lập ràng buộc `onDelete: Restrict` nhằm tuân thủ quy tắc toàn vẹn dữ liệu `BR-09`.
   - Sử dụng giao dịch tương tác `prisma.$transaction(async (tx) => ...)` kết hợp khóa dòng mức CSDL (Row-Level Lock `SELECT ... FOR UPDATE` qua `tx.$queryRawUnsafe`) trong các luồng mượn sách, trả sách và phân bổ hàng đợi đặt trước nhằm triệt tiêu race condition.

## 3. Các Phương án Thay thế Đã Cân nhắc (Alternatives Considered)

| Tiêu chí so sánh | PostgreSQL 16 + Prisma (Được chọn) | MongoDB (NoSQL) + Mongoose | MySQL 8.0 + TypeORM |
| :--- | :--- | :--- | :--- |
| **Mô hình dữ liệu** | Quan hệ chặt chẽ (Relational Schema) | Tài liệu phi cấu trúc (Document) | Quan hệ (Relational) |
| **Tính toàn vẹn ACID** | Rất cao, hỗ trợ đa giao dịch và khóa dòng | Yếu trên đa collection, dễ sinh dữ liệu rác | Cao, nhưng hỗ trợ partial index hạn chế |
| **Hỗ trợ Partial Index** | Hỗ trợ chỉ mục có điều kiện xuất sắc | Hỗ trợ partial index cơ bản | Hạn chế, cú pháp phức tạp |
| **Type Safety & DX** | Sinh type TypeScript/JavaScript tự động | Định nghĩa schema thủ công qua Schema | Dễ lỗi đồng bộ entities |
| **Lý do bác bỏ** | — | Bác bỏ do không đảm bảo tính toàn vẹn khóa ngoại `BR-09` và hàng đợi FIFO `BR-07` | Bác bỏ do thiếu tính linh hoạt trong migration và type-safety kém hơn Prisma |

## 4. Hệ quả và Đánh giá Tác động (Consequences)

### Tác động tích cực (Positive Consequences)
- **Đảm bảo toàn vẹn dữ liệu tuyệt đối:** Ràng buộc khóa ngoại và giao dịch ACID bảo vệ hệ thống khỏi trạng thái bất hợp lệ (ví dụ: sách được mượn 2 lần cùng lúc).
- **Trải nghiệm phát triển (Developer Experience):** Prisma Client tự động sinh mã tương thích với cấu trúc bảng, giảm thiểu 90% lỗi sai tên cột hay sai kiểu dữ liệu khi code.
- **Khả năng tái lập môi trường:** Toàn bộ lịch sử migration được lưu trữ phiên bản hóa trong thư mục `prisma/migrations`, giúp CI/CD và các thành viên dựng lại CSDL chính xác chỉ bằng lệnh `npm run db:migrate`.
- **Dữ liệu mẫu chuẩn hóa:** Seed script `prisma/seed.js` cung cấp dữ liệu giả lập sẵn cho 3 vai trò và 30 đầu sách để phục vụ demo và kiểm thử tức thì.

### Hạn chế và Biện pháp Giảm thiểu (Trade-offs & Mitigations)
- **Hạn chế:** Prisma chưa hỗ trợ khai báo chỉ mục một phần (partial unique index) trực tiếp trong file `schema.prisma` (ví dụ: chỉ cho phép 1 khoản mượn active trên 1 bản sao).
  - *Biện pháp giảm thiểu:* Nhóm viết trực tiếp câu lệnh SQL `CREATE UNIQUE INDEX ... WHERE returned_at IS NULL` vào file migration khởi tạo và thực thi trong quy trình CI.
- **Hạn chế:** Cần container Docker PostgreSQL hoặc cài đặt local service để chạy kiểm thử tích hợp hoàn chỉnh.
  - *Biện pháp giảm thiểu:* Nhóm thiết kế cơ chế mock module `../db.js` trong Jest để kiểm thử unit/API chạy độc lập trên máy sạch mà không phụ thuộc vào kết nối DB ngoài.
