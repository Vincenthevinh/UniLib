# ADR-004: Chiến lược Triển khai và Hosting trên Nền tảng Đám mây Vercel và Render

## 1. Bối cảnh và Đặt vấn đề (Context)

Dự án UniLib cần một phương án triển khai trực tuyến (Live Deployment) để phục vụ việc demo tương tác, kiểm thử chấp nhận người dùng (UAT), và chấm điểm nghiệm thu đồ án:
- Ràng buộc ngân sách là **0.00 USD** (không có kinh phí tài trợ cho máy chủ đám mây có phí).
- Cần tự động hóa quy trình phân phối sản phẩm (Continuous Deployment - CD): mỗi khi Pull Request được merge vào nhánh `main` sau khi pass CI, phiên bản mới phải tự động được build và cập nhật lên môi trường production mà không cần can thiệp thủ công.
- Yêu cầu phi chức năng:
  - `NFR-01`: Thời gian phản hồi trang tra cứu và danh mục sách đảm bảo tính khả dụng cao.
  - `NFR-03`: Toàn bộ kênh truyền thông tin xác thực và dữ liệu phải được mã hóa qua giao thức HTTPS (TLS/SSL).
  - `NFR-06`: Hỗ trợ đầy đủ các trình duyệt hiện đại (Chrome, Edge, Firefox, Safari) trên nhiều độ phân giải màn hình.

## 2. Quyết định Kiến trúc (Decision)

Nhóm T05 thống nhất lựa chọn giải pháp **Decoupled Cloud Hosting (Lưu trữ đám mây phân tách)** kết hợp hai nền tảng PaaS miễn phí hàng đầu:

```
[Người dùng / Trình duyệt]
        │
        ├─── (HTTPS - Static Assets & SPA Routes) ───► [Vercel Edge Global CDN]
        │                                                     │
        │                                                     ▼
        │                                             React 18 + Vite SPA
        │
        └─── (HTTPS - RESTful JSON API) ─────────────► [Render Cloud Web Service]
                                                              │
                                                              ▼
                                                     Node.js 22 + Express API
                                                              │
                                                              ▼ (Internal TCP)
                                                     [Render Managed PostgreSQL 16]
```

1. **Frontend Hosting trên Vercel Edge Network:**
   - Mã nguồn thư mục `src/client` được cấu hình triển khai tự động lên nền tảng Vercel.
   - Tận dụng hệ thống mạng phân phối nội dung toàn cầu (Edge CDN), tối ưu hóa thời gian tải trang (LCP < 2.5s theo `NFR-01`).
   - Tự động cấp phát chứng chỉ SSL/HTTPS miễn phí.
   - Tính năng Preview Deployments cho mỗi Pull Request giúp thành viên phụ trách UI/UX (Ánh) và BA (Nguyên) kiểm tra giao diện trực quan trước khi merge.
2. **Backend API & CSDL Hosting trên Render.com:**
   - Mã nguồn thư mục `src/server` được triển khai dưới dạng **Render Web Service** (môi trường Node.js 22).
   - Cơ sở dữ liệu được triển khai bằng dịch vụ **Render Managed PostgreSQL 16**.
   - Thiết lập cấu hình Web Service và CSDL trong cùng một vùng địa lý (Region: Singapore hoặc Frankfurt) để giảm thiểu độ trễ mạng (Network Latency) xuống dưới 10ms giữa API và DB.
   - Endpoint giám sát sức khỏe `GET /api/health` được cấu hình làm Health Check Path để Render kiểm tra trạng thái hoạt động của container.
3. **Cấu hình Bảo mật và CORS:**
   - Biến môi trường `CORS_ORIGIN` tại Backend được giới hạn chặt chẽ chỉ cho phép domain production của Frontend trên Vercel (ví dụ: `https://unilib-t05.vercel.app`).
   - Các biến môi trường nhạy cảm (`DATABASE_URL`, `JWT_SECRET`) được cấu hình an toàn trên Render Environment Dashboard, tuyệt đối không lộ ra bên ngoài.

## 3. Các Phương án Thay thế Đã Cân nhắc (Alternatives Considered)

| Tiêu chí so sánh | Vercel + Render (Được chọn) | AWS Free Tier (EC2 + RDS) | VPS tự quản trị (DigitalOcean / Linode) |
| :--- | :--- | :--- | :--- |
| **Chi phí hàng tháng** | 0.00 USD hoàn toàn | Dễ phát sinh phí ẩn nếu vượt quota | Tối thiểu 4 - 6 USD / tháng |
| **Công bảo trì DevOps** | Gần như bằng 0 (Zero-config PaaS) | Rất cao (Cấu hình VPC, SG, IAM, Linux) | Cao (Tự cài đặt Nginx, SSL certbot, firewall) |
| **Tự động hóa CI/CD** | Tích hợp sẵn theo Git push | Phải cấu hình GitHub Actions deploy phức tạp | Phải tự viết script SSH / Webhook |
| **Hỗ trợ HTTPS** | Tự động 100% | Phải cấu hình Certificate Manager & ALB | Phải tự gia hạn Let's Encrypt qua Cron |
| **Lý do bác bỏ** | — | Bác bỏ vì rủi ro phát sinh chi phí thẻ tín dụng và tốn thời gian cài đặt | Bác bỏ vì vi phạm ràng buộc ngân sách 0 USD |

## 4. Hệ quả và Đánh giá Tác động (Consequences)

### Tác động tích cực (Positive Consequences)
- **Chi phí vận hành tuyệt đối 0.00 USD:** Tuân thủ 100% ràng buộc ngân sách đồ án.
- **Bảo mật mặc định:** Toàn bộ lưu lượng truy cập đều được mã hóa HTTPS, không lo lắng việc gửi token xác thực qua kênh truyền không an toàn.
- **Quy trình bàn giao mượt mà:** Bất kỳ thay đổi nào được duyệt trên GitHub sẽ tự động được cập nhật lên bản live demo sau 1-2 phút, giúp giảng viên có thể kiểm tra nghiệm thu bất kỳ lúc nào.

### Hạn chế và Biện pháp Giảm thiểu (Trade-offs & Mitigations)
- **Cơ chế "Cold Start" của Render Free Tier:**
  - *Hiện tượng:* Gói dịch vụ miễn phí của Render sẽ tạm dừng (spin down) container Web Service nếu không có request nào trong vòng 15 phút. Khi có request mới, container mất khoảng 30 - 50 giây để khởi động lại.
  - *Biện pháp giảm thiểu:* Trước các buổi thuyết trình và chấm điểm nghiệm thu, nhóm sử dụng một cron script đơn giản hoặc công cụ uptime monitor (như UptimeRobot hoặc Cron-job.org) để ping endpoint `GET /api/health` mỗi 10 phút một lần nhằm giữ server luôn ở trạng thái "ấm" (Warm instance).
- **Hạn chế thời gian sống của PostgreSQL Free Instance trên Render:**
  - *Hiện tượng:* Render giới hạn phiên bản DB miễn phí trong 30-90 ngày.
  - *Biện pháp giảm thiểu:* Nhóm đã chuẩn hóa sẵn toàn bộ schema migration và seed script (`npm run db:migrate && npm run db:seed`), cho phép dựng lại toàn bộ dữ liệu CSDL trên bất kỳ instance mới nào trong vòng chưa đầy 1 phút.
